# 已实现的表演机制与可运行示例

效果提升不只来自换渲染器：使用同一套六姿态形象，让道具、人物反应和声音有先后；把“讲道理的卡片”变成一件事发生、主角受到影响。

| 机制 | 示例实现 | 新故事如何迁移 |
| --- | --- | --- |
| 预备→刺激→反应 | 通知音→手机长嘴→小人约0.14秒后惊一下 | 先给观众原因，再给角色反应；不同时弹出全部元素 |
| 累积与失控 | 44本书错开约0.043秒涌来，人物受压后缩 | 道具数与密度升级，冲突要在画面上发生 |
| 动静反差 | 洪水后切空白文档与光标 | 用安静延长尴尬，不一直震动、推镜 |
| 反应近景 | 半睁眼与哈欠姿态切换 | 表情可读优先，不依赖海报文字 |
| 具体小行动 | 敲两行字，中途改写 | 结果要可见；别只写“开始行动”标题 |
| 结尾回扣 | 同一通知再次出现，人物这次不慌 | 同一刺激、不同反应，保留末句与1秒以上尾韵 |

图集为3列2行、每格512像素，背景为不透明暖纸。当前实现是裁切姿态切换加GSAP二维变换，并非逐帧动画、真实嘴型或骨骼绑定；不能称“角色真实走路”。手机翻转时嘴和手必须跟着锚点走，顶行裁切避免串入下一格；细节见build-demo.mjs。

## 准备固定故事示例

仅用于复现已认可表演方向。新题按comedy-writing.md重新创作，不固定六镜、不永久用这十句。

安装包不含人声、字体、GSAP或第三方音效。先在已获准环境生成assets/examples/script.json的十句。时间轴JSON：duration、records（id/text/start/end/duration/pauseAfter，秒）和captions（text/startMs/endMs/timestampMs/confidence）。句窗需真实测量；短语按字数估算就明确标注，不捏造ASR置信度。

```sh
python3 <skill目录>/scripts/prepare_demo.py --output <新项目目录> --timing <timing.json> --voice <voice.wav> --font <中文字体.ttf> --gsap <gsap.min.js> --sfx-dir <现有media-use音效目录>
node <skill目录>/scripts/build-demo.mjs <新项目目录>
```

输出目录必须尚不存在。音效目录应有manifest.json及五种文件：notification、whoosh-short、pop、key-press、click-soft；不传时如实生成无音效版本，plannedCues仍保留用于后续补齐。

依HyperFrames技能执行check、逐场景快照和渲染。校验没有漏挂子场景、黑帧、截尾和遮挡字幕。图集重复裁切与书堆刻意重叠可能触发布局提示，只对证实故意的元素标注，不忽略整个场景的检查。当前实现不把检查通过当作主观有趣。

配乐候选放作品本地，原版/有BGM版共用同一人声和画面；音色和故事另轮比较，避免一次改太多而无法判断好在哪里。
