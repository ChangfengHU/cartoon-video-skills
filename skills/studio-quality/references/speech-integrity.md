# 配音完整性与返修

用于有锁定台词的配音制作、复用旧语音及声音返修。预置音色、语气指令、请求成功、时长正常都不能证明台词读全。

1. 冻结 `timing.json` 的 `segments`（唯一 `index`、`text`、音频 `file`、真实时长）。保存实际送入TTS的文本和安全参数，不保存请求密钥。复用旧音频也纳入检查，不继承未经核实的通过状态。
2. 混音前，从实际原始配音或完整干声做独立ASR，不给识别器答案提示。保存原始结果，并用 `audio_sha256` 绑定被识别文件，标明 `stage: source`。ASR文本不能来自字幕或剧本回填。
3. 运行 `scripts/speech_check.py --timeline timing.json --audio media/voice-only.wav --transcript qa/source-asr.json --out qa/source-speech-check.json`。退出码2表示差异或证据缺失，阻止把该声音版本标记为内容检查通过。自动检查只忽略标点、空白和字母大小写；不凭整体相似度、词语同音或故事大意相同放行。
4. 差异先定位：原始文件开头/结尾、对白分轨、最终混音依次对比。源文件已有问题就局部重配；源文件完整而成片丢失就查裁剪、覆盖、入点、增益与编码。不要用删字幕、改锁定台词或把“疑似ASR问题”写成pending来掩盖已知缺陷。声称听过须确实听过；没有听审能力就明确保留限制。
5. 每次局部重配先检查新源音频，再按真实时长重排受影响字幕、动作、音效、混音。已有成功片段冻结；云任务结果不明先恢复查询，不盲目重试。
6. 对实际最终MP4提取/识别音轨，以**最终MP4哈希**绑定 `stage: final` 的新ASR证据，重新运行同一检查。源声音通过不替代最终音轨检查。重渲染后旧证据失效。

识别歧义可用 `--review qa/speech-review.json` 逐项处理，格式为 `audio_sha256`、`script_sha256` 与 `resolutions` 列表，每项有检查生成的 `id`、`basis`、`reason`、`evidence` 相对路径及 `evidence_sha256`。`listened_asr_error` 必须有实际听审时间段与发现；`orthographic_equivalence` 仅限有语言学依据的同音同调写法差异，记录每一处理由，不能泛化成全局替换表、掩盖吞字、缺词、错调或新加词。脚本不会验证人是否真的听过或语言学理由是否成立，这部分仍需负责的编辑判断。

`content_gate=pass` 只表示本次文本完整性检查无未解释差异，**不代表听审、情绪、混音、字幕同步或发布质量通过**。QA分别记录内容检查、声音清晰度/表演、混音、最终声画同步。字幕按字符数估时不能冒充逐字对齐；有词级时间戳可先用作对齐依据，再检查实际显示。

存在未解决漏词，不交付为修复完成/发布就绪；可保存带明确状态的内部预览。最终听审未做则不能声称全片听审通过。ASR服务故障、无法消除的差异、能力未接入都要明确记录，不生成虚假通过。
