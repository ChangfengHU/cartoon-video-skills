# 从资料到成片

用于根据话题或资料包制作解读视频，以及发现调研与成片脱节的返修。虚构短剧仍可直接从故事进入；不要为纯虚构剧情强制联网。外部调研负责采集与事实核验，工作室负责接收、选择、表达和复核。

## 编导判断

建立 EDITORIAL.json，与剧本、镜头一起迭代。先读资料再作取舍，不能先选一个结论再只找支持材料。记录不同立场、资料日期、样本范围与缺口；同源转载不算独立佐证。互动量只说明该次样本的互动，不能推导播放量、完播率或某个设计导致成功。

每个发现记录它对目标观众的意义、证据强弱、可展示程度，以及选用或暂不采用的理由。频繁出现、新鲜、能解释清楚、与主题相关都可影响判断，但不做固定加权榜单，也不要求全部发现进入影片。用户指出一次遗漏后，复查同类决策机制，不把该对象写进通用必讲清单。

选择表达形式时比较真实素材、解释难度、角色表演价值和目标观看体验。记录适配理由；角色是演员资产，不等于风格。沿用用户明确指定的形式；不能只因上次用了某个人物或模板继续套用。

对每个入选发现，回答：观众应该理解什么；哪段台词或现场声音说明它；哪个具体画面能支持；需要完整播放、回放、标注还是示意。素材不能证明的判断明确标作分析、设想或待验证。无需解说的演示可用画面与短标注完成，但须记录为什么观众可以理解。视频长度由内容价值、动作完整性和真实音频共同决定，不凑固定镜头数。

## 热点现场解读

这是可选表达形式，适合已有可核查现场、操作或事件素材的解读。真实变化先让观众看见，随后解释意义与限制；开头承诺的内容在片中兑现，结尾给出判断或留下具体问题。无需固定科技人物、配色、语气、配乐、章节数或开场套路。

参考同行时记录其开场、论点、证据镜头和解释方式。研究素材与获准进入成片的素材分开登记。对设备界面、游戏动作等连续事件，先完整观察源片，再确定裁切与标注；不能让二创动画伪装成产品原生效果。

## 制作与复核

在完整制作前先做能暴露主要风险的代表段落，内部检查即可，沿用用户授权。台词自然度、画面可读性和声画对应无法由字段校验替代。配音先用实测文件定时间；语速参数不是精确倍速，导演情绪描述不等于调用了情绪API。字幕优先真实时间戳；若只能估算，标明方法和待复核范围。

音乐按本片选择并记录试听范围。延用已有授权曲目可以，但须说明本片适配理由。检查所有段落的音乐存在与电平变化，主动留白和断轨故障分别记录。全片听审必须实际完成，环境不支持时保留 pending。

render 前运行 `editorial_check.py EDITORIAL.json --stage plan`。它检查引用和落地完整性，不判断哪个题材更热门。

render 后从最终 MP4 检查入选发现是否传达、限制条件是否保留、声画是否吻合、开头承诺是否兑现。检查时间落到最终文件，并绑定 SHA256；换片后旧检查失效。运行 `--stage final`；未听审或未视觉复核可以交付待审版本，但不得标作质量通过。用户反馈只引用实际反馈。

将 EDITORIAL.json、SCRIPT、音频和镜头作为 production_state.py 的输入，沿用依赖失效机制。不要在这层暗中提交生成、重试收费任务或发布。

## EDITORIAL.json v1

- `schema_version`: 1；`topic`：本片主题。
- `style`: `{name, reason}`，名称不限制枚举。
- `sources`: `[{id, locator, scope}]`，locator 为资料位置，scope 写日期、时间段或样本边界。
- `findings`: `[{id, claim, kind, source_ids, decision, reason}]`。kind 为 fact / observation / interpretation / hypothetical；decision 为 include / omit / defer。fact 和 observation 必须引用资料；所有取舍需理由。
- `beats`: `[{id, finding_ids, message, visual, audio, evidence_role}]`。evidence_role 为 evidence / illustration / commentary；audio 可写明确的无旁白设计；每个入选发现至少被一个 beat 承接。未采用发现不要混入 beats。
- 最终阶段添加 `artifact`: `{path, sha256, duration}`，path 相对 JSON 所在目录。
- `reviews`: `[{beat_id, dimension, status, range, artifact_sha256, note, evidence}]`。dimension 为 editorial / visual / audio；status 为 pass / fail / pending。已检查项提供最终片区间、观察和证据文件路径；pending 不伪填区间。每个 beat 的三个维度分别记录，缺失会报告 pending。技术检查继续写 QA，不混作编辑结论。

校验结果只说明记录完整程度。`reported_pass` 代表有已填写的观察，不能证明观察真实、内容准确或用户认可。
