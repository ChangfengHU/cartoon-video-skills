# 发布与回执

使用vyibc-douyin.get_capabilities、discover_accounts，存在多个账号才确认选择。先准备标题（实测上限30字）、描述（900字）、最多5话题；限制可能变化，以当前返回为准。

文案围绕故事钩子、互动、话题，少写制作信息。AI/虚构声明按内容及平台要求保留；通过选择无需公开署名的授权音乐实现干净文案，不能漏掉已用曲目的必要署名。

封面尽量提供横竖两版，但当前MCP的自定义封面仍属实验能力，可能publication_cover_failed。若明确未提交且账号读回未出现目标作品，可选择默认视频帧封面继续；如只能默认选帧，不声称自定义封面生效。优先让片头本身具备封面可读性。

当前实际遇到remote_upload_file_too_large：111.4MB在上传前失败，33.1MB发布版通过。未探测精确服务上限，不把33MB或100MB当成固定平台上限。保留高清母版，必要时另做小体积上传版并核验清晰度。

发布只走已批准的auto-parse工作流MCP。poll get_publish_task；creation receipt包含awemeId才证明创建，审核状态独立判断。已发布可只读创作者列表核对标题、时间、文案；reconcile工具只适用uncertain任务。结果不确定不得换requestId重投；完全失败且确认未提交时，改变素材/封面应建立新输入请求并记录旧失败，原requestId不能更换payload。

目前topics是文案文本，未保证原生话题实体。AI声明、封面、审核、账号分别报告核验范围，不因任务done就声称全部功能通过。不得为了测试插件再发布一遍旧作品。

发布后按真实作品ID读回作者、文案和AI声明，记录核验层级。发布任务报published或作品页面可读，不等于已获得明确审核通过状态。自定义封面失败的回退须留原错误、无提交证据与新请求记录；默认封面不写成自定义封面成功。工作室快照在发布前生成时，后续发布回执单独存档，不改写历史QA为全项通过。

## Fleet 发布作品登记

发布前从本片角色锁取真实 `characterIds`，提供稳定 `studioTaskId` 和实际上传 MP4 的 `sourceSha256`，随 `publish_video` 一起传入。无角色的作品传空数组，不能把人物显示名称当 ID，也不能用示例视频覆盖发布历史。制作任务 ID 是本片的稳定标识，不冒充另一个系统已经存在的 Task。

MCP 保存上下文；轮询 `get_publish_task` 收到真实创建回执后，自动登记 Fleet。后台每小时对已保存且未登记的任务作有限量只读补偿。检查响应 `registration.status`，必须为 `registered` 才能声称已关联；`retry_pending` 或 `missing_context` 时保存原任务 ID 与上下文，调用 `register_published_video` 补登记。此工具只读取旧任务回执，不上传、不再次发布。不能因登记失败改变 requestId 重发作品。

登记以平台、账号、作品 ID 去重；同一作品可关联多个角色。用 `list_published_videos` 按 `characterId`、`studioTaskId` 或账号读回验证。Fleet 自媒体管理的“已发布视频”分类展示登记作品，角色档案中另有“已发布视频”，与示例作品分开。平台创建、审核、公开可见性分别记录；未确认审核不能写审核通过。

现阶段自动登记适配抖音 auto-parse 的真实回执。其他平台尚未接入，不宣称全平台已发布历史自动发现。旧作品需有原发布任务回执才能补录；手填一个链接不是发布成功证明。上下文一旦绑定不可静默改写，冲突需检查原记录。任务创建成功但保存上下文失败时，保留回执并只重试登记；没有任务 ID 的不确定结果仍先核对原请求。
