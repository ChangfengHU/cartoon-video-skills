# 角色的场景与表演资产

新建或明显扩展角色时，角色档案必须描述独立显示名、稳定内部 ID、检索别名及命名依据。参考作者名、作品名不默认成为角色名；更名不意味着已解决形象授权或相似性问题。已有认可形象保持身份锁，只调整明确要求的部分。

从本集分镜推导场景需求，并区分长期常用场景与本集临时场景。禁止将“卧室”“跑步”等标签当作已经生成的背景。按剧情需要生成真实场景图片，实际传入角色或认可画面的画风参考；记录地点、日夜、服装、镜头方向、可站区、脚底线及前后遮挡。场景数、动作数由剧情确定，不固定六格或套用最近作品。

场景须有人物合成样帧：检查比例、透视、落地、光线与道具接触。人物站在床前不等于已表现躺床，平移人物不等于行走。连续动作包保存真实中间姿势、帧时长、脚底锚点与起止姿势；渲染按主时间线绝对时间选帧，不用独立 ticker。只有两张表情交叉淡入时如实称表情转换。

项目保存 `PRODUCTION_PACK.json`，用 `scripts/production_pack.py check <file>` 验证文件与哈希。它不会判断审美。角色 scene_requirements 的每项须关联具体场景；动作须关联真实帧及连续采样证据。缺失项目不能标记制作资产齐备，已完成部分可作为候选交付。

入库沿用 image kind，场景使用 technical.asset_kind=scene；technical.scene 包含 location/time_of_day/version/character_names，character_ids 保存关联。场景不能混入人物卡片或冒充人物三视图。角色 technical.scene_assets 保存场景 id/title/location/time_of_day；双方新版本同步更新，原版本保留。远端入库回执和实际浏览器检查须覆盖“场景”分类、完整图、角色配套场景入口、手机与深浅主题。公共插件不携带私有素材。

改名、换场景、换动作帧会使相应镜头与成片检查过期。保留旧片，按实际新片连续采样对照；技术校验与用户认可分别记录。发布画面不常驻工具名、工作流名或未经设计的系列标签。
