# Studio development instructions

## Independent open-source research

For research requests and new or substantial skill/MCP/plugin capabilities, the user explicitly requires an independent subagent to search GitHub and relevant open-source communities while the primary agent inspects existing local capabilities and integration constraints.

- Delegate a concrete bounded comparison task. Do not redundantly delegate simple questions, routine fixes, or already-researched unchanged work. Disclose unavailable delegation tools.
- Verify repository identity, license, relevant source, dependencies, platform compatibility, credential/cost requirements, and maintenance evidence. Distinguish README claims, source inspection, and actual runtime tests.
- Compare candidates against existing studio components. Document what to reuse, adapt, or reject and why; produce a combined design instead of merely listing repositories.
- Keep dated evidence and unverified items under `docs/research/`. Pin revisions and retain required license notices when actually importing code. Research alone does not authorize paid services or imply installation/testing.
- Preserve existing HyperFrames, asset management, voice, and platform boundaries unless evidence justifies changing them. Do not duplicate a capability simply to expose another tool name.
- Track coherent changes in Git. Report local commit, remote push, installed-skill sync and Fleet deployment separately; none implies the others.
