# 角色制作与入库工作流

先读项目简报和当前工作室策略，再查私有资产库的角色档案与认可版本。已有角色沿用身份；多个独立人物不必同画风。不要把最近一部作品的题材、服装、镜头数量或音色写成所有项目的默认值。

## 按实际产物推进

1. **来源**：用户给图可直接用；指定个人浏览/点赞时用behavior，指定平台帖子时用对应平台MCP。记录原链接、采集时间和实际查看的本地图片。区分“看过”“用作生成输入”“仅用于调研”；最终档案显示实际使用图。来源不能以标题或列表封面猜人物特征。
2. **设计**：交给vyibc-character-design。写长期定位/动机/性格/说话习惯/适用与避用场景/身份锁，具体职业、服装变体及本集关系另存。由戏份决定表情、姿势、道具和连续动作需求；格数齐全不等于可以演戏。后续生图必须实际输入定稿参考并保存非敏感请求回执。
新增或扩展角色的场景、表演资产必须执行[场景与动作包](references/scene-action-pack.md)：独立显示名、真实常用场景图片、合成样帧与实际连续姿势；Fleet中场景单列并关联角色。

3. **选声**：交给voice-production，先执行当前用户的voice_policy.excluded_voice_ids，再按角色挑当前实际可用且授权适用的预置/复刻声。收藏不代表适合角色，更不等于默认。无需用户逐个A/B选；自主选定一个真实短样音，记录provider、model、voice_id、实际参数、自然度/角色适配的依据和未听审项。换声不覆盖已认可旧片。
4. **可选示例片**：由cartoon-video-studio→studio-director→HyperFrames制作。按真实音频时长组织镜头和反应，音乐随故事重新选择。整图平移不能冒充步态；需要接触、迈步或口型时补对应动作或明确采用漫画表达，不能靠持续抖动掩盖。
5. **检查**：实际图片逐张查看，实际MP4逐镜和连续动作取样。用选定认可作品比较身份、构图、表演、节奏、声音和收尾，写保留项/本次变化/未验证项。先跑release_check.py，技术通过不自动升级认可。用户认可的维度与版本精确保存；认可画面不等于认可旧音色。
6. **入库与页面**：按[交付契约](references/contract.md)存角色、私有参考缩略图、真实样音和示例视频。读取最新资产后合并metadata，用asset_revise保留版本。用浏览器验证鉴权、缩略图和放大、音视频实际播放、深浅主题及手机布局；保存读回回执。没有实际部署/读取结果，不称已同步。

## 可恢复执行

用现有cartoon-video-studio/scripts/production_state.py登记任务、输入哈希、依赖和远端job ID；网络超时先恢复原任务，不能盲目再提交生图或TTS。`scripts/workflow.py init --project <项目> --brief <项目内简报.json>` 创建阶段任务；不会调用平台、生成或自动批准。已有账本逐项校验后复用，不覆盖。

完成后用 `scripts/workflow.py check <项目>/CHARACTER_WORKFLOW.json` 核对来源文件、选声策略、输出和页面证据绑定。它只检查证据，不判断美感。资料缺失或旧项目补录时明确pending，继续可做工作；不得把补录字段说成当时已执行自动化。

普通新人物是带版本的私有数据资产，不要求每人单独建skill。只有出现独立、可复用的制作技法才增加风格skill。插件安装不携带私人素材、个人收藏、账号登录、API密钥或定时器。参考图经鉴权展示，不将私有浏览内容写进公共插件或公开R2。

角色视频的动作规划、预检与认可基线按[连续表演工作流](references/continuity-workflow.md)执行。已有资产包仍是素材来源；CONTINUITY只关联分镜、当前输入和实际试片，不另造角色身份。

涉及步态、切图闪动或人物分层返修时，执行[步态与分层返修](references/gait-and-layer-repair.md)：先核对素材与新旧实际试片，区分显隐修复和动作自然度；未解决项不自动成为通过的质量基线。
