# 平台内制作与质量延续

当工作室迁到另一个 Agent 平台或新机器时，先证明当前会话能制作，再沿用平台执行；外部维护者代跑渲染不能作为平台验收。平台名称、版本回执、模型自称均不能替代实际调用证据。

## 执行环境

- 从平台实际 shell 查询 Node、FFmpeg、HyperFrames、Chromium、字体与所需 Python 模块。SSH 登录 shell 的 PATH 不代表 Agent shell 的 PATH。
- 预检不能只查版本号：确认实际 FFmpeg 路径具有所选编码器（例如 libx264），并通过主合成入口导出短片。必要时安装项目内编码器并显式绑定路径；子场景的 `<template>` 文件不能直接当独立渲染入口。保留失败命令、退出码及修复后的短片证据。
- 使用平台会话的持久项目目录。某些 Codex 适配器原生线程在临时只读目录运行，应通过平台提供的 bash/fs/jobs 操作工程，不能据此要求关闭全部沙箱。
- 技能描述被发现不等于技能正文及资源已加载；角色搜索命中不等于参考图、动作、场景和声音已下载。冻结实际文件及版本，实际看图；工具返回URL不等于模型看到图像。
- 核对真实模型ID、推理配置、图片模态与图片预算。切换平台时先保持已验证生成通道；更换生图服务需用相同参考图比较人物、透明边缘、姿势与尺寸，不能仅凭服务名称认为等价。
- 长渲染交后台job，保存job ID、命令、工程位置和进度；通过平台查询至终态。进程/会话重建后先读制作状态，再决定恢复，不重复提交尚未对账的远端任务。

## 阶段恢复与图片传递

- 长会话出现连续传输重连时，不把已有结果重新生成。将前期素材、合成预览、最终渲染验收分别记成阶段；每阶段保存制作状态、实际文件/哈希、外部任务ID、通过与拒绝项、下一步命令。监督者可在确认旧执行停止后，用新平台会话接续同一工程，不能让两个执行者同时修改工程。
- 新会话先读阶段交接并对账。已完成的配音/生图直接复用；结果尚未确认的任务先查询；失败版保留。短会话恢复是一项容错措施，不代表底层断线已修复。
- 模型能通过平台读取文件，不代表原生生图服务能够解析同一个本地路径。编辑/参考生图必须核实参考传输；路径明确不可用时，可以先把全部所需参考实际附入模型上下文，再使用工具支持的最近图片引用方式。不能同时传两套引用方式，也不能退化成只在文字里描述角色。失败后核对任务与预算，再决定是否重试。
- 图片数据写入持久文件，状态只存路径、尺寸、哈希与工具回执摘要；不要把整段base64写进交接或反复全文读取。图片实际检查仍通过图像输入完成。

## 分层角色表演

同机位对话或连续动作适合使用固定场景与独立演员图层。表情换图时不应重绘整个背景；确需切机位时按镜头设计切换，不能用全屏闪烁掩盖角色不一致。

生成的多格演员图不是已经注册好的精灵。先核对实际分辨率、格数和目标屏幕占比；意外生成手机外框、整页展示板或错误画幅时拒绝，不以裁切放大掩饰不足。逐格检查不透明边界、脸位置、完整手脚与道具；按身体/道具实际接触点对齐，不能按图片外框自动缩放后就认为对齐。需要比较相邻格的角色比例和接触关系。眨眼、视线、吸气、犹豫与反应为表演服务；不要机械规定每秒换图或禁止有动机的复用。

复用旧工程的场景层时，先检查RGBA不透明覆盖范围：原来依赖床铺、桌面等前景遮住的透明下半区，换故事后可能从人物夹缝露出黑底。黑洞不一定来自演员抠图；应逐层隔离定位，并在实际合成底色上复核，不可反复侵蚀人物黑发/裤子来掩盖舞台缺口。

合成先检查人物与场景的比例、站立/坐姿所在平面，以及手和道具的接触。中近景应保留完整可理解的上半身，或让裁切自然落在画幅边缘；不要靠另画一块大色板遮住缺失身体。前景、UI与道具的材质和透视应服务当前画风；程序绘制并不天然合格，生成图片也不天然合格。相同参考图换生成通道后，仍需实际比较画风、边缘和可表演性。

每段动作写清预备、接触、结果及另一人物的反应。图片数量与镜头数量分开登记：20张画面曝光60次不能称60张独立素材。素材清单记录实际尺寸、裁切、放大和对应镜头；不把“希望2048”记成“生成2048”。

按本片真实配音时长安排停顿与动作。复用音效仍需对齐新动作；沿用的音乐/音效不能称新增。源语音完整性通过后仍检查最终混音；改变声音或视频文件后旧哈希证据失效。导演情绪文字与实际TTS参数分别记录。

## 平台验收

1. 先用冻结素材复现认可作品，分离运行环境差异。参考MP4只用于对照；不能把下载原片当重新生成。
2. 再在新会话制作新片段，覆盖当前故事的难点，例如双人反应、物体接触与换姿势，记录失败及修复。
3. 抽帧、ASR和上传也可能是长任务，应保存后台job和阶段状态。抽帧进程被超时中止后，先核对数量与文件完整性，不能把半写入图片交给图像检查；重试前确认旧作业已停止。
4. 最终实际MP4按场景和连续动作采样，与参考中相应表现比较；声音完整性、混音数值和实际听审分别记录。没有人工听审就标未完成，不用ASR替代。
5. 一次复现成功只能证明该工程可运行；新故事成片及多个独立会话案例才用于评估初步稳定性。不能保证随机生成逐帧一致，也不能将技术通过写作审美通过。

把通用方法放在技能，把角色和风格的校准素材放在对应档案，把本片时间点和返修留在工程。先交付R2候选；发布及账号写入仍需用户明确指令。
