# 角色设计

交付实际人物图与可恢复的角色资产，不用参考页、提示词或任务 ID 冒充生成完成。既可单独设计一个角色，也可为整部故事提供演员组；不是“只生成漂亮女主”的固定模板。

## 先判断交付边界

- 用户要实际形象：生成并展示图片。已说“直接做”时，不在搜索、方案或确认参考阶段反复停下。
- 用户只要参考/讨论：只研究，不消耗生成额度。只要人物时不扩写故事、不生成视频、不发布社交平台。
- 已有定稿：先读取用户指定的角色资产与反馈，保持身份；“换衣服”“补表情”不是重新设计脸。全部重做才另建身份，普通改版保留 ID、递增版本，不覆盖已批准版本。
- 明确会影响结果的假设：画风、年龄/物种、角色数量、用户保留/拒绝的特征和交付物。用户给了故事就从戏份提取人物，无法判断的重要角色才问，不自行无限扩充演员组。
- 默认新主要角色提供一张正侧背三视图与一张表情图；用户指定的数量/格式优先。动物按物种设计侧面和背面；无背面的物品说明相应视角，不硬套人体比例。路人可仅交轮廓/服饰稿，必须写明简化原因，不算缺失的主角交付。

## 设计人物而非堆形容词

把需求拆成：叙事身份/动机、面部与体态、发型、服饰道具、表情/动作习惯、材质光影；同时列出禁止沿用的方向。
“丧、灵动”可以分别落在静态神情和受到刺激后的反应；“邋遢”是否指碎发衣褶还是污损，结合用户原意判断。漂亮不等于尖下巴、极端腰腿比、统一网红脸。不要以眼袋皱纹替代所有疲惫表演。

有多个人物时，先建立共用画风卡（维度、材质、比例规则、线条/着色、时代），再为每人设计脸型、体态、剪影、配色、动作的区别。性别、年龄、性格、戏份各自决定造型，不让所有配角复制女主；双胞胎/替身等同源人物是显式例外。
主角、配角、反派都服务故事，而不是人人都套某一审美预设。用户已确认的风格只约束相应作品，不升格为全局偏好。

## 参考来源与执行能力

需要外部灵感或用户指定小红书时，读 [能力选择](references/providers.md)。参考可来自用户图片、小红书或已有授权角色库；不要求每个角色都联网。
实际查看图片后，分别记录参考用于脸型、发型、服饰、表情还是画风。标题不是外貌证据；滤镜、透视和镜面自拍不能证明真实身体尺寸或年龄。借用可见设计语言，不把不同真人脸拼接成所谓原创，也不推断未提供的真人身份属性。

只找少量能改变设计决策的素材，保留来源链接。遇到登录/平台限制如实返回，不循环刷新、绕过限制或重启用户浏览器。没有参考也可根据已确认描述设计原创人物，但不能说看过不存在的素材。

使用当前环境允许的真实生图工具；有内置 imagegen 时按它的 skill 生成/编辑。否则复用已连接生图能力。先验证工具真实参数，不能将单参考图字段当多参考图列表。若后端不支持需要的模式，说明差异并采用已授权的可用路径，不能悄悄降级后声称效果等价。

## 生成与一致性

1. 角色定稿/三视图锁定身份、发型、体态、服装。三视图为正面、严格侧面、背面，同尺度同基线，全身和鞋完整；不是三个近似三分之二侧脸。用户需要单图肖像时不强制拼图。
2. 表情、换装、追加视角引用实际定稿图，不仅靠文字。表情应体现角色的剧情反应，避免只有嘴角变化。四格可作为默认，但用户数量优先。
3. 多角色先各自定稿，再做同框比例对照；同框图用于查身高关系、撞脸和画风，不替代各自的主参考。每个角色独立 ID，不能把整组参考图交给模型后失去人物对应关系。
4. 独立角色可在可用车道内并行；同一角色的后续表情依赖实际定稿。同框依赖所需角色版本。用户已批准的参考版本才冻结给下游。
5. 保存任务 ID、实际提供方和状态再轮询。超时且提交结果不明时恢复原任务，不重复付费提交。默认每个产物至多两次定向修正；仍不合格先给出具体问题与现有候选，不无限生图。

## 验收后再交接

逐张看图：身份是否一致、三视角是否正确、服装道具是否漂移、手脚是否明显错误、表情是否可区分、同框人数/比例是否正确、是否符合用户审美。
质量状态分开保存：生成成功、技术校验、视觉检查、用户批准。脚本通过不能自动把视觉或用户批准设为通过；没有实际看图不能填视觉通过。
不满意时指出具体偏差，修对应维度，不把用户拒绝的精致职业感再换颜色交付。

读 [角色资产格式](references/asset-contract.md)，保存角色 ID/版本、提示词与参考来源、实际图片、验收意见和用户批准依据。使用现有项目清单则做字段映射，不另建冲突的主清单。角色资产库只复用已授权范围；品牌私库不是通用公共存储。
默认给原图与一页可浏览预览；用户指定 R2 时使用已有上传能力，验证远端可下载且内容完整后再报告。带真实参考素材的公开预览须在授权范围内；密钥、签名凭据和私人素材不进入公开页面。
后续故事/视频只消费准确的角色版本和参考图，不能把资产清单当成已经绑定的3D模型，也不能保证视频绝不变脸。

临时输入和可重建输出确认无需继续使用、远端恢复源有效、无其他进程依赖后才按精确路径清理。保留唯一成果、源码、定稿和必要证据；本 skill 的检查器不会自动删除文件。

## 示例、工具与安装

- 仅选择“成年大学生·清纯微丧·三维动画”方向时读 [已批准案例](references/campus-soft-slump.md) 与 `references/campus-approved.json`。它是一个可选成功案例，不是所有年龄、性别、物种的默认。
- 资产检查：`node scripts/character-check.mjs <cast.json>`；离线，无网络、无生图、无删除。`--approved` 额外要求已批准版本及整组同框检查，供交给故事前使用。
- 验证代码：`node --test scripts/*.test.mjs`。测试保证结构/安装边界，不证明审美质量。
- 本地安装：`node scripts/install.mjs [skills目录]`。仅创建本 skill 的符号链接；相同来源重复执行无变化，遇到其他来源停止，不覆盖。
- 远程安装：`bash <(curl -fsSL https://skill.vyibc.com/install-vyibc-character-design-0.1.0.sh) codex`，Claude Code 把末尾改为 `claude`。必须显式指定目标；校验包 SHA-256，相同文件重复安装不改动，已有不同文件则停止。远程安装是文件副本，不使用本地链接卸载器；移除前核对归属并保留修改，不能盲删。
- 卸载：`node scripts/install.mjs --uninstall [skills目录]`。仅删除指向本来源的链接；保留源码、角色图和项目资产。重新运行安装即恢复。
- 安装 Skill 不会自动连接 MCP、继承登录或获得生图额度；新会话是否自动发现，以客户端实际加载为准。本轮可显式读取本文件使用。
