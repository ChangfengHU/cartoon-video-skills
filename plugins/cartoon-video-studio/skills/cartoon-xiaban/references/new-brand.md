# 后续建立其他角色品牌

仅在用户要求创建新角色/新品牌 skill 时用此流程，不因为一个新主题自动另建角色。

采用“一套角色品牌，一个独立 skill”的简单结构。渲染引擎与 TTS 运行环境可以共用，角色素材、声音、音乐和已确认偏好独立。当前不需要额外建设 MCP、数据库或发布平台。

## 新品牌最小档案

- 新的唯一 `brand_id` 和 skill 名称，例如 `cartoon-<角色名>`；描述中写清可辨认的触发词，避免所有品牌争抢普通“做视频”请求。
- 角色：已认可参考图、比例/服装/辨识点，必要的姿势与表情；注明原创生成、真人授权或其他来源。
- 声音：方向、候选、实测文件、获准复用的参考、服务/模型、音色 ID 与参数；未确认就留空并保持候选状态。
- 视觉与动作：调色板、线条/材质、字幕/构图习惯、动作节奏与不适合的表达。
- 音乐：可以没有；有时保存 track ID、短标志音、循环段、来源与授权，而不是只有“轻快 BGM”四个字。
- 版本与资源清单：文件、哈希、来源、审批状态；一条实际成片及反馈可在完成后追加。

用 `skill-creator` 建新 skill。可以借鉴本包的目录和 `prepare_project.py`，但先清空旧 `brand_id`、选定声音、音乐和原角色图，不把下班小人复制后换名称冒充新设计；为新资产重新计算哈希。

形象定了而声音没定是合法的部分完成状态。不要先填虚假的 voice ID、样片路径、音乐文件或“用户已批准”。

## 改版与隔离

同一个角色更换表情/服装小变体，通常作为该品牌的新资产版本；彻底改变身份和声音时由用户决定是新版本还是新品牌。引用旧素材不要直接覆盖文件。

每次新作品在其目录保留 `BRAND_LOCK.json` 与素材快照。该快照不随 skill 后续更新而改变，方便解释旧片使用的形象/声音/风格；它不承诺随机生成模型逐字节重现。

用户说“用之前那个”但存在多套候选且不能可靠辨认时，简短确认品牌名。不要把一个品牌的声线、配乐或角色悄悄混进另一个品牌。

新品牌只需加载自己的资料，不一口气加载所有品牌的参考。共享的是执行能力，不是创作人格。
